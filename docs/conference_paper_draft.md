# SentinelChain: Causal Attack-Chain Reconstruction for LLM-Grounded Network Forensics

## Abstract
Traditional network intrusion detection systems (NIDS) like Suricata and Zeek are proficient at generating atomic alerts, but often fail to provide the context necessary for holistic incident response, leading to alert fatigue. In this paper, we introduce **SentinelChain**, a novel network forensics framework that shifts from passive log summarization to active, causal attack-chain reconstruction. SentinelChain employs a Selective-Deep Packet Inspection (DPI) trigger to autonomously capture context-rich packet slices upon alert generation. These slices are mapped into an Evidence Pack and processed by a Causal Correlation Engine utilizing Directed Acyclic Graphs (DAGs) and MITRE ATT&CK state transition rules. By anchoring large language models (LLMs) exclusively to these reconstructed, causally-validated Evidence Packs via a Retrieval-Augmented Generation (RAG) pipeline, SentinelChain eliminates forensic hallucinations. We evaluate SentinelChain on the CICIDS2017 dataset, demonstrating a significant reduction in false positives and a novel approach to automated, grounded threat reporting.

## 1. Introduction
Modern Security Operations Centers (SOCs) are overwhelmed by the sheer volume of alerts generated by rule-based network monitors. While tools like Zeek provide excellent flow-level metadata and Suricata offers precise signature matching, reconstructing a multi-stage Advanced Persistent Threat (APT) requires manual correlation of disparate logs. Recent attempts to apply Large Language Models (LLMs) to this problem often result in "hallucinations," where the model infers missing context based on its training data rather than the actual network telemetry. SentinelChain bridges this gap by enforcing strict causal constraints on the data fed to the LLM.

## 2. Methodology
Our framework consists of three primary components:
1. **Selective DPI Trigger**: A continuous listener that monitors Suricata alerts (e.g., `eve.json`). Upon triggering, it defines a temporal window $[T_{start}, T_{end}]$ and automatically extracts the corresponding raw packet slices using `tshark`. This reduces storage and processing overhead compared to full packet capture.
2. **Causal Correlation Engine**: Extracted flows and alerts are mapped into a Directed Acyclic Graph (DAG) using `NetworkX`. Nodes represent specific alert states, and edges represent causal transitions weighted by MITRE ATT&CK tactical sequences (e.g., *Reconnaissance $\rightarrow$ Initial Access*).
3. **Forensic Groundedness RAG Pipeline**: The causally validated chains are structured into JSON Evidence Packs. The LLM generates reports strictly from this context. A Forensic Groundedness Score (FGS) audits the report to ensure no claims exist outside the provided Evidence Pack.

## 3. Preliminary Results (Correlation Engine v1)
Our initial implementation of the Causal Correlation Engine (v1) successfully builds DAG representations of network flow data. By applying rule-based weights to state transitions, the engine filters out logically inconsistent alert sequences (e.g., Data Exfiltration without prior Initial Access or Lateral Movement), significantly isolating the true attack chains. Emulated multi-stage attacks using Caldera provided ground truth labels, allowing us to validate the path-finding algorithms.

## 4. Conclusion and Future Work
SentinelChain presents a robust architecture for automated network forensics. By combining Selective-DPI, causal graphing, and grounded LLM generation, we provide SOC analysts with verifiable and contextually complete incident reports. Future work will focus on integrating the complete RAG reporting loop and formally benchmarking the execution speedup and F1 score against baseline models like HOLMES.
